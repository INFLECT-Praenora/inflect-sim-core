The simulation core — one sepsis model, every engine

Q What can the simulation core do? This investigation takes ONE real model — the BioGears sepsis core — and shows four capabilities on it, each as something you can open and run, not a claim on a slide: 1. COMPOSITION — run the same spec under interchangeable engines (study 01). 2. ENSEMBLES — run a severity × engine batch in one orchestrated sweep (study 02). 3. ORCHESTRATION / WORKFLOWS — compose modules into a pipeline and hand an Antimony/SBML file between engines (study 03). 4. PERFORMANCE — profile where the compute goes and how fast each engine is (study 04). A fidelity backbone (study 05) keeps it honest: where the engines agree, and where they do not.

Claim

The simulation core runs one sepsis specification under three interchangeable engines — BioGears (C++ physiology), Tellurium (exact SBML via roadrunner/CVODE), and a PyTorch surrogate — composes and orchestrates them into workflows (including passing an Antimony/SBML file between engines), runs them as ensembles, and does it performantly (seconds to hours across engines; a ~40,000× surrogate tier). Every capability below is a runnable artifact; the surrogate is a fast approximate tier (bounded, not yet clinically accurate), not a drop-in replacement.
